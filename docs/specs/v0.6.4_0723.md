二、增加 Flow Match TTS step 调节（开发者模式）
背景：
当前 C++ 中 TOTAL_STEP=8 固定，但模型已经支持 current_step / total_step 参数，因此不需要重新导出模型。

需求：
1. 在「设置 → 开发者模式」增加 TTS Step 调节开关。
2. 支持 step 1～8 调节，用于测试生成速度和音质差异。
3. 参数链路：
Kotlin UI → JNI → C++ → Flow Match 推理。
4. 默认保持 step=8，不影响普通用户。
5. 开发者模式开启后可以手动修改。
6. UI 需要展示当前 step 值。

注意：
已测试：
- step 4 基本不可用；
- step 4~5 偶尔音质异常；
- step 8 当前作为默认稳定方案。
因此不要改变默认体验，只提供实验能力。

四、TTS 切句策略优化

背景：
当前文本到语音流程存在两层切句：
- SentenceSplitter：根据标点和长度进行第一次切分；
- SuperTonicTtsBackend：再次限制最大长度进行二次切分。

重复切句会导致语音片段过短，连续播放时出现明显停顿，整体听感断断续续。

需求：
1. 优化切句逻辑，避免多层重复切分。
2. 保留 SentenceSplitter 作为主要切句入口，Backend 不再主动改变语义切分结果。

新的切句策略：
- 一级标点（。！？；）优先作为完整语音片段。
- 二级标点（，、：）不立即切分，仅在句子长度达到 18～28 字时作为候选切点。
- 超长文本（40～50字以上）优先寻找最近标点切分，避免生硬截断。
- 尽量保持完整语义，减少过短语音片段。

实现要求：
- 不引入大模型或复杂 NLP，只通过规则优化。
- 保证短句响应速度不下降。
- 增加开发调试能力，可查看实际切分后的文本片段，方便测试不同策略。
- 优化后重点测试连续聊天场景，减少机器人式停顿，提高陪伴感。


开发者模式：
增加「TTS切句调试」选项：
- 显示实际切分后的文本片段，方便测试。
- 支持调整关键参数：
  - 二级标点最小切分长度；
  - 最大句子长度；
  - 是否允许 Backend 二次切分。
