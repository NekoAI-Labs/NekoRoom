## 首次加载live2d慢

第一次加载，默认就是背景，只有背景，然后就是那个2D角色，很久才出来，大概3~5秒

 关于 Live2D 首次加载慢——实测确认，不是错觉

  刚才 cold-launch 抓到的时间轴（adb logcat 打点）：
  01:12:46.771  Splash Screen 出现
  01:12:47.351  Activity 首帧 (activity resumed)
  01:12:47.315  背景 setBackground(600x750) 立刻上屏 ← 用户看到"背景已就位"
  01:12:47.729  开始读 fenmaololi.model3.json
  01:12:47.745  16 个表情/装扮 exp3.json 全部解析完（16ms 很快）
  01:12:52.242  onLoadDone ← 模型真正显示到屏幕

  **从"背景可见"到"角色出现"= 4.9 秒。**你观察的 "3~5 秒" 是准的。

  为什么慢：
  - 47.745 → 52.242 这 4.5 秒完全花在 GL 线程上：解 PNG 纹理（FenmaoLoli 有多张 2K/4K 贴图 → 皮套 + 表情 + 装扮）、GPU 上传、编译 shader、首帧 draw call。这些在 native
  里串行跑，无法用 Kotlin 协程加速。
  - 同一时刻主线程还在初始化 TTS/LLM（[语音输入加载中] 初始化 TTS… 也是 47.313），CPU 有点抢。

  为什么以前没这么明显：
  不是变慢了，是"背景先出、角色后到"的对比被放大了。v26 的 nativeSetBackground 让背景 quad 在 GL surface 上一到就先渲染，所以你能明确看到"背景 + 空的 4 秒 + 角色"。老版没有这个
  bg quad，早期就是一片黑等到全部完成才 pop 出来，用户主观上没有分离感。

  要不要修？我看有三条路：

  1. 占位剪影（工作量 1h）：在 live2d_container 里放一张半透的角色轮廓 ImageView，onLoadDone 时 fade out。视觉上不再"空 5s"，但实际加载时间不变。
  2. 提前 warm-up（工作量 2h）：在 splash / 权限授予之后立刻新开线程读 fenmaololi.moc3 + 纹理到 direct ByteBuffer，等 GL surface 就绪时 native 直接 upload。可能砍 1-2 秒。
  3. 接受它：这是 Live2D SDK 的固有冷启动代价，桌面版 nizima / Cubism Viewer 也是这个量级。

  推荐 1（省事 + 用户体感差异最大）。要哪一条？
