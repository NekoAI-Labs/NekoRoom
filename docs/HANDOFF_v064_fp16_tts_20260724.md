## 3. v0.6.4 已完成内容

### 3.1 本地 LLM 与默认模型

模型注册集中在 `app/src/main/java/com/moeavatar/model/ModelManager.kt` 的 `LLM_MODELS`：

| 显示顺序 | 模型 id | 大小（约） |
|---:|---|---:|
| 1 | `minicpm5-1b-fp16` | 2.17 GB |
| 2 | `minicpm5-1b-q8` | 1.31 GB |
| 3 | `minicpm5-1b-q4` | 1.00 GB |
| 4 | `minicpm5-1b-q4-embed8` | 826 MB |
| 5 | `minicpm5-1b-q4-embed4` | 726 MB |

- 下拉列表依次显示 FP16、Q8、Q4、Q4-Embed8、Q4-Embed4，便于优先选择高精度版本。
- **新安装**的默认 `activeLlmId` 是训练好的 `llm-neko`（`jiaohui/qwen35_08b_nekoneko-MNN`）；已有用户的 SharedPreferences 选择不覆盖。
- `REGISTRY` 的能力中心 LLM 卡片也指向 Neko，以便首启下载推荐的是猫娘模型；MiniCPM5 是可选模型，不能因列表排序而改变默认模型。
- `ModelManager.activeLlm()` 会在偏好模型未安装时优先复用设备上任何已安装 LLM，避免升级后强制重下模型。

### 3.2 MiniCPM5 思考关闭与采样参数

- `ModelManager.disableThinking()` 只对 `minicpm5-1b-*` 在下载目录 `config.json` 中确保写入：

  ```json
  {"jinja":{"context":{"enable_thinking":false}}}
  ```

- 此逻辑在 native 加载前执行，不需要重新导出模型，也不改 MNN 权重、JNI 或 C++ 推理代码。
- 不要统一覆写模型的 `temperature`、`topK`、`topP` 或 `mixed_samplers`。Linux 验证中，替换 FP16 原始 sampler 列表会在多轮后退化为重复“喵喵”；模型目录的 `config.json` 是本地模型采样参数唯一来源。
- Qwen/Neko 不注入 MiniCPM5 的 `jinja.context`，以免改变各自模板语义。

### 3.3 TTS 性能、Quality 与切句

#### Quality

- 配置：`LlmConfig.ttsSteps`，键名 `tts_steps`，范围 `3..8`，**新用户默认 6**。
- UI：设置 → 开发者模式 → `TTS Quality`；用户看到的是 Quality，不暴露 Flow/steps 实现细节。
- 值会沿 Kotlin → JNI → C++ 的现有参数链路传入 SuperTonic；无需重新导出 TTS 模型。
- 数值越小越快、质量越低。Quality=4 的速度理论上可比 Quality=8 高约 50%，但必须以真机试听为准；4–5 可能有音质异常，默认 6 是当前速度/稳定性折中。
- 已有用户若保存过 `tts_steps`，升级不覆盖；设置页面显示当前保存值。

#### 语音模型与音色路径

- 下载模型：`jiaohui/NekoVoice-v1.1`。
- 必需文件：`dp.mnn`、`te.mnn`、`ve.mnn`、`vocoder.mnn` 和 `voices/catgirl_style.json`。
- 音色文件必须位于 `models/tts/voices/`，不要再平铺在模型根目录。`LlmConfig.ttsVoiceId` 保存 id，当前默认 `catgirl_style`，路径按 `voices/<id>.json` 解析，为未来多音色保留接口。

#### 切句规则

主入口是 `app/src/main/java/com/moeavatar/tts/SentenceSplitter.kt`：

- 一级标点（`。！？；.!?;`）或换行立即切分；
- 二级标点在文本达到约 18 字时才作为候选切点；
- 无合适标点时，硬切上限为 **56 字**；
- `SuperTonicTtsBackend` 不得对已分好的文本再做第二层语义切分。

这是一项首包与连续性的取舍：正常有句号的首句不会等到 56 字；无标点长文本可减少过短片段和可听停顿。不要随意取消一级标点优先级，也不要恢复 Backend 二次切句。

### 3.4 开发者模式、性能面板与本地多轮

配置都在 `LlmConfig.kt`，UI 主逻辑在 `LlmChatActivity.kt`：

- `devMode`：默认关闭；开启后显示二级性能/调试选项。
- `showPerfLine`：显示聊天页性能小字。
- `performanceLogsEnabled`：记录性能并输出 `MoeAvatar.*` 日志；性能面板会保留最近最多 3 次数据并显示平均值。不足 3 次则按已有次数平均。
- 性能面板包含设备信息与 LLM/TTS 摘要，并提供“复制”按钮；复制后 Toast 为“已复制性能参数”。
- `localMultiTurn`：默认 `false`。关闭时，本地后端只接收系统提示词和当前用户消息；开启后才带入会话历史。当前小模型多轮容易被上下文污染，默认关闭是有意设计，不要改回默认开启。

实现位置：`LlmChatActivity.sendMessage()` 构建 `requestTurns`。修改对话策略时，必须保留本地后端仍会注入系统提示词这一前提，不能让“关闭多轮”变成没有角色身份提示词。

### 3.5 在线服务商与下拉框

服务商注册在 `app/src/main/java/com/moeavatar/llm/ProviderPreset.kt`：

| Provider | 地址 | 默认模型 | 关闭思考协议 |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-v4-flash` | `thinking.type=disabled` |
| SiliconFlow | `https://api.siliconflow.cn/v1` | `Qwen/Qwen3-8B` | `enable_thinking=false` + `chat_template_kwargs` |
| MIMO（小米） | `https://api.xiaomimimo.com/v1` | `mimo-v2.5-pro` | `thinking.type=disabled` |
| Agnes 2.0 | `https://apihub.agnes-ai.com/v1` | `agnes-2.0-flash` | Qwen 协议 |

- `LlmConfig.enableThinking=false` 时，MIMO 会发送 `{"thinking":{"type":"disabled"}}`；这是 MIMO 明确要求的关闭方式。
- 旧用户若只保存了 Base URL，`ProviderRegistry.inferByBaseUrl()` 能识别 `xiaomimimo.com` 并迁移为 MIMO。
- Provider Spinner 使用 `styledModelAdapter()` 和 `bg_model_dropdown`，避免系统白色弹窗。
- 曾有两个已修复 UI/交互坑：
  1. Spinner 自身有 `bg_input` 时，Adapter 的选中项不能再设置 `bg_input`，否则出现“框中套框”；当前行视图必须透明。
  2. 监听器与初始 `setSelection()` 的时序会吞掉用户第一次选择。当前用 `initializingProvider` + `spProvider.post { ... }` 忽略初始化期间回调；不要简化回旧的 `spinnerReady` 写法。

### 3.6 SME2 与性能日志说明

- SME2 是否可用由构建出的 MNN native 库和设备 CPU 特性自动决定；App 内开关不负责强制启用指令集。
- 性能日志只用于观测与定位，不会改变模型导出格式、计算图或 CPU 指令选择。
- 语音首包优化已通过动态 Shape 模型与现有 native 库完成；此分支不需要重新导出 `mnn_fp16` 线上语音模型。

## 5. 已知限制与不要踩的坑

1. 当前开源本地小模型对猫娘系统提示词、多轮角色扮演的遵循仍不稳定；这属于模型能力问题，不能靠无限加长提示词解决。Neko 微调模型适合默认单轮体验；本地多轮保持实验开关。
2. 不要把本地 Neko 身份提示词换成在线 API 的长提示词；本地模型使用短版提示词和独立表情规则，长提示词会挤占小模型有效上下文。
3. API Key、模型、APK、日志都不进 Git。模型下载到 `getExternalFilesDir("models")`，大文件放 `/mnt/d`。
4. 弹窗使用 `BottomSheetDialog` + `bg_sheet`，不要改用 `AlertDialog`；后者可能让 Live2D 的 GL media-overlay 黑屏。
5. 所有持久化配置进入 `LlmConfig`，不要在 UI 或 native 层写死默认值；默认值变更必须兼顾“新用户默认”和“旧用户保存值不覆盖”。
6. 当前工作树可能存在未跟踪的 `docs/specs/v0.6.4_bug*.md` 和 `docs/specs/v0.6.5-phonecall.md`，它们是需求文档，未经确认不要混入功能提交。

   - `/home/jhx/Projects/AIGC/voice-align/docs/VAD最简部署.md`
   - `/home/jhx/Projects/AIGC/voice-align/docs/04VAD对比报告.md`
3. 状态机至少包含：待机/正在听 → 检测到语音/录音 → 静默结束并发送 → LLM/TTS 回复 → 可打断；所有状态必须可取消和回收音频资源。
4. 用户说话或点击“打断”时，立即停止 TTS 播放，切换到拾音状态，并给予轻量震动/视觉反馈。
