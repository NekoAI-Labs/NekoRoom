## 0. 你首先必须理解的两件事

### 0.1 两棵源码树 —— **改错地方等于白干**

| 树 | 路径 | 作用 | 编译能力 |
|---|---|---|---|
| **归档树（改这里 + git commit）** | `submit/mini-app/apps/NekoChatMini/` | git 跟踪的真源码，提交都在这 | ❌ 缺 native `.so`/部分资源，不能独立 build |
| **工作副本（编译这里）** | `apps/Android/NekoChatMini/` | 真正 `gradlew` 出 APK 的地方 | ✅ 但**不在 git 里**，别在这里 commit |

**只在归档树改代码 → cp 到工作副本 → 工作副本 build & 装机 → 验证 OK → 归档树 commit**。反过来会
让工作副本堆没入 git 的改动，下次同步会覆盖丢失。

> ⚠️ 项目的 git 根是 `submit/mini-app/.git`。`MNN/.git` 是空占位，**不是这个项目的仓库**。

### 0.2 同步命令（改完必跑）

```bash
# 在 submit/mini-app 目录下
SRC=apps/NekoChatMini
DST=../../apps/Android/NekoChatMini   # 相对 submit/mini-app 的路径；用绝对路径也行

# 单文件同步（推荐；只 cp 你确实动过的文件）
cp $SRC/app/src/main/java/com/moeavatar/chat/LlmChatActivity.kt \
   $DST/app/src/main/java/com/moeavatar/chat/LlmChatActivity.kt

# 一次同步整个 java + res 目录（安全，不覆盖 native jniLibs / build/）
rsync -av --delete \
  --exclude 'build/' --exclude '*.iml' --exclude '.gradle/' \
  $SRC/app/src/main/java/  $DST/app/src/main/java/
rsync -av $SRC/app/src/main/res/  $DST/app/src/main/res/
```

> ⚠️ **禁止 `rsync --delete` 整个 `apps/Android/NekoChatMini/`**：会干掉 `app/src/main/jniLibs/`
> （手工放的 `libMNN.so` / `libmoeavatar_llm.so`，不在 git）。只同步 `java/` `res/` `assets/`。

## 1. 构建 / 装机 / WSL 里调 Windows adb

**环境**：`compileSdk 35`，`minSdk 26`，NDK `26.1.10909125`，CMake `3.22.1`，`arm64-v8a` only，竖屏锁定。

```bash
# ── 1) 构建（在工作副本）
cd apps/Android/NekoChatMini
./gradlew :app:assembleDebug     # 首编 ~2-3 min；增量 ~15-30s

# ── 2) 装机（WSL 里用的是 Windows adb.exe）
ADB=/mnt/d/softwares/platform-tools/adb.exe

# 关键坑：adb.exe 是 Windows 进程，install/push 的**本地文件参数必须是 Windows 路径**！
# 先把 APK 挪到 D 盘，再用 D:\... 引用；直接给 /home/ 或 \\wsl$\ 会失败/卡住。
cp app/build/outputs/apk/debug/app-debug.apk /mnt/d/nekochat.apk
timeout 90 $ADB install -r 'D:\nekochat.apk'

# ── 3) 启动（applicationId = com.neko.chat，跟 namespace com.moeavatar 不同！）
# 用 am start -n com.moeavatar.chat/... 会失败；用 monkey 走 LAUNCHER intent。
$ADB shell monkey -p com.neko.chat -c android.intent.category.LAUNCHER 1

# ── 4) 冷启动计时
$ADB shell am force-stop com.neko.chat
$ADB shell am start -W -n com.neko.chat/com.moeavatar.chat.LlmChatActivity | grep TotalTime
```

**adb shell 内部路径正常写 Linux 风格**（`/sdcard/...`），只有 `install`/`push` 的**本地路径**要 Windows 化。

## 2. 调试 / 看日志 / 抓截图

```bash
ADB=/mnt/d/softwares/platform-tools/adb.exe

# 本 App 全部 TAG（都以 MoeAvatar. 开头）
$ADB shell logcat -s MoeAvatar.Chat MoeAvatar.Live2D MoeAvatar.LLM MoeAvatar.TTS MoeAvatar.MsDL

# 只看崩溃（native SIGSEGV 之类）
$ADB logcat -b crash

# 前台窗口 / 焦点（盲操作前 tap 前后确认没跳到别的界面）
$ADB shell dumpsys window | grep mCurrentFocus

# UI 结构（找按钮坐标）
$ADB shell uiautomator dump && $ADB pull /sdcard/window_dump.xml /tmp/ui.xml

# 读设备上的 SharedPreferences（App 是 debuggable → 可 run-as）
$ADB shell run-as com.neko.chat cat /data/data/com.neko.chat/shared_prefs/moeavatar_llm.xml

# 截图 —— 注意 Live2D 是 GL media-overlay，截图里角色/背景常是黑的，玻璃效果只能真机目视
$ADB shell screencap -p /sdcard/x.png && $ADB pull /sdcard/x.png /tmp/x.png

# 清应用数据（重放首启引导 / 换模型）
$ADB shell pm clear com.neko.chat
```

- `LlmConfig.devMode` 默认开 → 所有 `MoeAvatar.*` TAG 输出 Verbose；关掉只留 Warn+。
- native 每秒一条 `DIAG`（scale/tx/ty）是**正常诊断日志**，别当 bug。

### ❌ 未完成（下一位 agent 接手）

#### 3.1 Live2D 首次冷启动 3~5s 空档 —— **有方案未合入**

**现象**：首次进入聊天时，背景瞬间出现，Live2D 角色 3-5 秒后才出（用户感知"卡死"）。
**根因**：GL 线程首次贴图解码+上传耗时（Live2D SDK 层不可避），非新增 bug；v0.6+ 因为 native
`nativeSetBackground` 让背景先秒出，反而暴露了这段空档。
**用户已批准方案 1（chibi 占位淡入，约 15 行代码 / 3 文件）**：

```xml
<!-- app/src/main/res/layout/activity_llm_chat.xml
     把 live2d_container FrameLayout 从自闭合改为开/闭标签，加子 ImageView -->
<FrameLayout android:id="@+id/live2d_container" ... >
    <ImageView
        android:id="@+id/live2d_placeholder"
        android:src="@mipmap/ic_launcher"
        android:layout_width="200dp"
        android:layout_height="200dp"
        android:layout_gravity="center"
        android:alpha="0.9"
        android:contentDescription="@null" />
</FrameLayout>
```

```kotlin
// app/src/main/java/com/moeavatar/live2d/Live2DController.kt
// 在 onLoadErrorListener 附近加：
var onFirstReadyListener: (() -> Unit)? = null

// 在 onLoadDone 的 glView.queueEvent { ... } 之后加：
android.os.Handler(android.os.Looper.getMainLooper()).post {
    onFirstReadyListener?.invoke()
}
```

```kotlin
// app/src/main/java/com/moeavatar/chat/LlmChatActivity.kt
// onCreate 里 live2d = Live2DController(...) 之后、live2d.onCreate(...) 之前：
val placeholder = findViewById<ImageView>(R.id.live2d_placeholder)
live2d.onFirstReadyListener = {
    placeholder.animate().alpha(0f).setDuration(300)
        .withEndAction { placeholder.visibility = View.GONE }.start()
}
```

**验证方式**：`adb shell pm clear com.neko.chat && adb shell am start -W ...`，观察启动后前 3s
是否看到占位猫头，5s 内是否淡出。启动器图标本身就是粉紫色 chibi 猫，跟主题匹配，不需要新素材。

#### 3.2 ASR native 长期潜伏竞态

`libNN.so` 的 `MNN::ThreadPool` 单例被 LLM/TTS/ASR 共享，ASR 尾包 decode 可能与 LLM Session 撞车
导致 SIGSEGV（野指针）。跟 v0.6.2 本次改动无关，但 v0.6.2 后由于在线首字更快、TTS 更早启动，触发率
升高。定位与修复思路见 `docs/bugs/bug0722.md`。**建议单开分支** `fix/asr-race`，别塞进本 PR。

## 4. 代码规范 & 提交规范（务必遵守）

来自项目 `myrules.md` + `submit/mini-app/CLAUDE.md`：

1. **API Key / 密钥绝不进 git**。`LlmConfig.openAiApiKey` 默认 `""`；测试时用的 key 只填在设备 SP 里，
   不写在源码或文档里。（用户之前泄露过 SiliconFlow key，已让其在
   `cloud.siliconflow.cn/account/ak` 轮换。）
2. **模型 / APK / 大文件不进 git**：APK 暂存 `/mnt/d/`，模型走 `getExternalFilesDir("models")`（应用
   私有目录，免存储权限）。
3. **可配置项进 `LlmConfig`，不写死**（模型名、URL、阈值、超参）。
4. **弹窗只用 `BottomSheetDialog`**，不要用 `AlertDialog`（AlertDialog 的白卡+全屏 dim 会让 Live2D
   GL media-overlay 渲成黑屏 / 角色消失）。
5. **改完立即 commit**。分支名 `feat/xxx`、`fix/xxx`、`docs/xxx`；commit 消息用 `feat:` / `fix:` /
   `refactor:` / `docs:` 前缀，含版本号（如 `fix: v0.6.2 xxx`）。**从不** `git commit --no-verify` /
   `git push --force`。
6. **每次迭代更新** `docs/CHANGELOG.md`（Features/Fixes/Refactor/Known Limitations），必要时更新
   `docs/ROADMAP.md`。
7. **`README.md` 保持可复现**（部署/push/运行流程），别删除现有 section。
8. **KISS / YAGNI / DRY**：只写用户明确要的代码，不加抽象、不加 fallback / 兜底除非现场触发。评论
   默认不写；写就写"为什么"不写"是什么"。
9. **只改工作副本编译验证，OK 后同步归档树，由用户/统一 commit**。
10. UI 材质约定（磨砂）：容器 `@drawable/bg_sheet`、输入框 `@drawable/bg_input`、描边按钮
    `@drawable/bg_btn_outline`；配色 `text_primary / secondary / tertiary` + `accent_pink`。

## 5. 常见误区速查

| 症状 | 原因 | 修法 |
|---|---|---|
| 改了代码 build 出 APK 但装机无效果 | 忘了 cp 到工作副本 | `cp 归档→工作副本` 再 build |
| `adb install` 卡住 | APK 路径是 `/home/...` 或 `\\wsl$\...` | 先 `cp /mnt/d/`，再 `install 'D:\...'` |
| `am start -n com.moeavatar.chat/...` 报错 | applicationId 是 `com.neko.chat` | 用 `monkey -p com.neko.chat` 启动 |
| 截图里角色/背景是黑的 | GL media-overlay 截不到 | 真机目视；日志验证 `nativeSetBackground` 已回调 |
| 弹窗一出 Live2D 消失 / 黑屏 | 用了 AlertDialog | 换 BottomSheetDialog + `bg_sheet` |
| 在线 API 返回 500 字 HTML 塞进字幕 | 未走 `ApiErrorMapper` | 在 catch 里判 `ApiException`，用 `outcome.uiSummary()` |
| 提示"未安装模型" 后按下载没反应 | 应用私有目录没模型 & 用户没在能力中心点下载 | 在能力中心点下载；开发预置可用 `scripts/push_models.sh` |
